# 多用户隔离实施计划

## 需求与边界

- 用户可自行注册普通账户，或使用用户名和密码登录；管理员可管理账户状态与重置密码。
- 每位用户只能读取或修改自己拥有的订阅配置及其节点、规则、策略和预览。
- 公开订阅和规则 URL 继续由配置随机 token 保护，保持现有客户端 URL 可用，不暴露用户信息。
- 既有单用户数据库迁移后，所有历史数据归入引导创建的 `admin` 用户；既有 `ADMIN_PASSWORD` 成为该账户的初始密码。

## 设计

- 新增 `users` 表：`id`、唯一 `username`、scrypt 密码哈希、`role`（`admin`/`user`）、`enabled` 与时间戳。
- 为 `subscription_configs` 新增 `owner_user_id`；节点、规则和设置通过配置归属隔离，禁止直接以 ID 跨用户读取或写入。
- 为 `sessions` 新增 `user_id`。升级时删除旧 session，要求重新登录，避免无归属 session 获得任意账户权限。
- 首次检测到旧 schema 时，创建 `app.db.pre-users.bak`，再在一个 SQLite 事务中完成用户、配置归属和 session 迁移。
- `ADMIN_PASSWORD` 只用于首次引导 `admin` 账户；公开注册只能创建 `user` 角色，管理员可启用/停用与重置用户密码。
- 每个新注册或由管理员创建的用户都会自动获得一份独立的“默认配置”，使首次登录即可开始管理订阅。
- 认证分为 `requireUser`（任何已登录用户）和 `requireAdmin`（仅管理员）。所有配置 API 都必须使用 `requireUser` 加上配置所有权检查。

## API 契约

- `POST /api/login` 接收 `username` 与 `password`；缺省用户名兼容为 `admin`。
- `POST /api/register` 使用同源校验与登录限流创建普通用户，并直接建立 session。
- `GET|POST /api/users`、`PATCH /api/users/[id]` 仅管理员可用，用于列出、创建、启用/停用和重置密码；管理员 API 可创建任意非管理员账户。
- 原有 `/api/configs`、节点、规则、设置与预览 API 返回或操作当前用户拥有的配置；越权 ID 一律返回 `404`。
